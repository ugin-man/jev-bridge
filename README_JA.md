# Jev Bridge

公式TypeSafeスキルと公式SDKを土台に、実行・接続の便利な部分を足す非公式ツールです。
公式スキルの内容を私たちが書き直して配布する形にはしません。

## 役割

Jevの能力、質問の設計、使い方の知識は公式スキルと公式ドキュメントに任せます。
APIへの通信と応答の読み取りは、依存ライブラリとして導入する公式TypeSafe SDKを使います。
こちらに残すのはMCP・コマンド・Pythonからの共通実行、キーの保管、ローカル使用量管理、
一括処理、結果保存です。同梱のjevスキルは、この実行部分だけを説明する補助です。

## 導入

このリポジトリを普段のAIで開いて、こう伝えます。

> HANDOFF.mdを読んで、公式TypeSafeスキルとJev Bridgeをこの環境に導入・更新して。既存の設定は維持して。技術的な操作は任せるので、本当に不足している情報や許可だけ聞いて。

AIは導入済みの公式スキルを再利用します。なければ公式の導入方法を一つだけ選びます。
こちらのインストーラーは公式スキルを上書きしません。公式スキルをインストールできない
環境では公式のファイルを直接読み、利用可能な接続経路を使います。
毎回の判定や一件ごとにスキルを取り直す必要はありません。

Python 3.11以上が必要です。通常のパッケージ導入で公式TypeSafe SDKも導入します。
MCPとOSの資格情報保管庫は必要に応じて追加します。公式SDKがなくても入力の無通信検査は
できますが、実APIの呼び出しにはSDKが必要です。旧式の独自通信への自動切替はしません。

## 変えない部分

用途・会話の言語・アプリを決めつけません。質問の機械向け入力はAIが作ります。
APIキーはローカルの非表示入力や秘密情報管理機能から設定し、チャットには貼りません。
利用者が認めた材料と件数だけを送信します。使用量の上限は調整できますが、料金を厳密に
保証する上限ではありません。途中失敗や未実行を分け、失敗時に勝手な再送をしません。

公式に任せるのは公式の更新方法で更新し、独自の実行部分だけをこのリポジトリで保守します。
SDK更新は互換テストを通してから取り込みます。GitHubの更新だけでPCの導入済みファイルが
自動更新されるわけではありません。

TEST_REPORT.mdに実施済み・未実施の検査を分けて記録します。模擬応答のテスト成功は、
本物のJevの精度やアカウントの利用可否を確認できたという意味ではありません。
