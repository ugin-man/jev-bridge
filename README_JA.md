# Jev Bridge

普段使っているAIに、やりたいことを伝えてJevを使うための非公式ツールです。
質問の組み立て、入力形式の検査、実行、結果の説明はAI側が担当します。
利用者がJSONを書く必要はありません。言語を指定するための必須項目もありません。

## 最初にすること

このリポジトリを、ファイルを読んでローカル操作できるAIで開き、こう伝えます。

> HANDOFF.mdを読んで、この環境でJevを使えるように導入して。既存のモデル・認証・ほかの連携は維持して。技術的な操作は任せるので、本当に不足している情報や許可だけ聞いて。

Codex専用ではありません。スキルを読み込める環境、ローカルMCPに対応する環境、
コマンドを実行できる環境、自作のPythonプログラムから利用できます。
ただし、ローカル操作も接続経路もないチャットに文章を貼るだけでは動きません。
各アプリでの実機確認が済んだことと、共通規格に対応したことは区別します。

## 導入の選択肢

Python 3.11以上が必要です。通常のコマンド利用は追加ライブラリ不要です。
MCPを使う場合は公式MCP Python SDK、macOSやLinuxの安全なキー保存を使う場合は
keyringを追加します。導入操作はAIに任せて構いません。

スキルのインストーラーには共通の配置先、Claude用、プロジェクト内、任意の配置先を
選ぶ機能があります。既存内容の更新は明示的な更新操作を使い、古い内容を別の場所に
バックアップします。既存のモデル選択欄や認証設定は書き換えません。

APIキーはローカルの非表示入力か、既存の秘密情報管理機能から設定します。
チャットやGitHubには貼りません。WindowsではDPAPI、対応するmacOS・Linux環境では
OSの資格情報保管庫を使います。保管庫がないサーバーでは環境変数を使えます。
平文への自動切り替えはしません。

## 使い方

「Jevでこの資料の矛盾を確認して」「この候補から条件に合うものを選んで」など、
目的と材料を伝えます。用途は商品照合に限定しません。AIは必要な判断を組み立て、
同じ資料への独立した質問をまとめ、結果を読み取ります。Jevが文章を生成しないことは、
AIとの組み合わせで大きな仕事を扱えないという意味ではありません。

外部への送信なしで確認するモードと、実APIを使うモードは別です。
Jevに送る材料と別途クレジットを消費する可能性を確認したうえで実行します。
許可済みの同じ仕事について、毎回同じ確認を繰り返す必要はありません。

既定の件数・サイズ・時間制限はローカルの設定で調整できます。最大20件しか設定できない
制限は撤廃しました。ただし、公式仕様のScore最大10段階、Choice最大255選択肢は
残しています。料金を通貨単位で保証する仕組みではありません。

## 確認状況

模擬応答のテスト、実際のMCP通信、本物のJevの応答、各デスクトップアプリでの操作は
別々に確認します。最新の結果はTEST_REPORT.mdと対象コミットのGitHub Actionsを見てください。
GitHubを更新しても、PCに導入済みのスキルは自動更新されません。

開発・導入の詳細はREADME.md、HANDOFF.md、SOURCES.mdにあります。
