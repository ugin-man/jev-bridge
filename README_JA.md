# Jevを日本語で使うスキル

バージョン1.0.0 / 2026年9月17日

「この2つの商品が同じか見て」「この文章を分類して」と普通に頼むための、Codex向けの非公式スキルです。
いま使っているLLMがJev用の質問を作り、実行し、結果を日本語で返す手順をまとめています。あなたがJSON・Python・true/false・フィールド名を入力する必要はありません。

## 最初にすること

ZIPをすべて展開して、`INSTALL.cmd`を開きます。コピーが終わったら、Codexで新しいチャットを開き、次のように伝えてください。

> Jevスキルを使って。接続状況を確認して、赤いマグカップの例を試せるところまで準備して。必要な操作は任せる。APIへの送信は、何を送るか説明してから確認して。

スキルが見つからない場合はアプリを再起動してください。キーが未設定の場合だけ、`SET-KEY.cmd`を開いて非表示の入力欄へキーを入れます。キーはチャットに貼りません。前のWorker/Helperにキーがある場合は同じ保存先を利用できる設計です。

Python 3.11以上が必要です。Pythonを見つけられない、スキルを読み込まない、といった場合は、展開フォルダーをローカルCodexで開き、`HANDOFF_FOR_CODEX.md`を読ませてください。自分でコマンドやコードを書く必要はありません。

## 使うとき

> Jevで、この2つの商品説明が同じ製品についてのものか確認して。違うところと情報不足を分けて教えて。

> Jevで、この問い合わせを「返品・配送・支払い・その他」に分類して。

> さっきと同じ条件で、次の20件も判定して。

材料が会話にない場合は、文章・ファイル・取得可能なURLなどを渡します。Jevが自動でネットを検索するわけではありません。

## このパッケージが変えるもの

スキルをユーザーフォルダーの `.agents/skills/jev` に追加します。主モデル、Gemini、MCP登録、Codex認証、承認やサンドボックスの設定は変更しません。別内容の同名スキルがあれば上書きせず停止します。
以前のJev Workerの導入は必須ではありません。同梱の小さな接続スクリプトを使う経路があります。新しいサーバーを起動し続ける必要もありません。

## 確認しておくこと

スキルの作成とローカル検査は済んでいますが、あなたのデスクトップへのインストールと、本物のJev APIへの接続はこの作成環境からは確認していません。詳しくは `TEST_REPORT.md` に記載しています。
Jevの利用はTypeSafe側のAPIクレジットを使います。購入や自動チャージは行いません。LLMによる質問作成・結果説明の処理も残るため、あらゆる単発依頼で総コストが下がるわけではありません。
本パッケージはモデル選択欄にJevを追加せず、普段のLLMを窓口としてJevを使います。

`CHECK.cmd`は外部通信なしの自動検査です。検査では本物のJevの知能・精度を評価していません。

## データとキー

APIに送るのは、依頼から作った材料と質問、モデル名だけです。接続スクリプト自体にフォルダー走査、ブラウザ操作、購入・出品機能はありません。LLMが材料を集める際も、ユーザーが指定した範囲とホストの権限に従うようスキルへ記載しています。

既存のWorkerまたはHelperが選ばれれば、その保存済みキー・設定・使用量カウンターを利用します。キーを新しい場所へコピーしません。キーを入れ直す場合は、共有している元ツールにも影響します。

新規保存時は通常 `.codex/tools/jev-skill` を使います。Windowsではキーを現在のユーザーのDPAPIで暗号化します。これは端末侵害や同じユーザーで動く悪意あるソフトウェアからの完全な保護ではありません。

ローカルの既定制限は200要求/日・要求本文10 MiB/日です。同じ保存先を使う処理で共用します。金額の上限やアカウント全体の請求を保証するものではありません。失敗時も自動で再送せず、上限を勝手に引き上げません。

## 取り外し

Codexを閉じて、追加した `.agents/skills/jev` フォルダーだけを削除するとスキルを取り外せます。`.agents/skills` 全体は削除しないでください。APIキーや使用履歴は別の保存先に残り、既存Worker/Helperは変更されません。TypeSafe側でのキー失効は別の操作です。
